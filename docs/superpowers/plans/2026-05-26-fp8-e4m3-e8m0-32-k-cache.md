# FP8 E4M3 E8M0 32 K Cache Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add CUDA K-cache support for `--cache-type-k fp8_e4m3_e8m0_32`, with Q quantized to FP8 inside KQ matmul, then validate with PPL.

**Architecture:** Reuse `GGML_TYPE_FP8_E4M3_E8M0_32`, existing CUDA set_rows, and existing native FP8 matmul. The only new runtime entry is allowing this type for K cache and rejecting unsupported non-CUDA or flash-attn combinations.

**Tech Stack:** llama.cpp, ggml, CUDA, cuBLASLt, CMake, shell smoke tests, `llama-perplexity`.

### Task 1: Red Smoke For FP8 K Cache CLI

**Files:**
- Create: `tests/test-kcache-fp8-e8m0-generate-smoke.sh`
- Modify: `tests/CMakeLists.txt`

- [ ] **Step 1: Add the failing smoke script**

Create `tests/test-kcache-fp8-e8m0-generate-smoke.sh`:

```bash
#!/usr/bin/env bash
set -euo pipefail

BIN="$1"
MODEL="$2"
TMP_OUTPUT="$(mktemp)"
trap 'rm -f "${TMP_OUTPUT}"' EXIT

CUDA_VISIBLE_DEVICES="${CUDA_VISIBLE_DEVICES:-0}" \
GGML_CUDA_FP8_E8M0_NATIVE_NO_FALLBACK=1 \
"${BIN}" \
    -m "${MODEL}" \
    -p "The capital of France is" \
    -n 4 \
    -c 512 \
    --batch-size 512 \
    --ubatch-size 512 \
    --n-gpu-layers 40 \
    -t 32 \
    --cache-type-k fp8_e4m3_e8m0_32 \
    --cache-type-v f16 \
    --kv-unified \
    --no-warmup \
    --no-display-prompt \
    > "${TMP_OUTPUT}" 2>&1

grep -q "flash_attn    = 0" "${TMP_OUTPUT}"
grep -q "K (fp8_e4m3_e8m0_32)" "${TMP_OUTPUT}"
grep -q "V (f16)" "${TMP_OUTPUT}"
grep -q "q\\*k src0{name=cache_k_l0.*type=fp8_e4m3_e8m0_32" "${TMP_OUTPUT}"
```

### Task 3: Focused KQ Test

**Files:**
- Modify: `tests/test-vcache-fp8-e4m3-e8m0.cu`

- [ ] **Step 1: Add KQ-shaped FP8 test case**

Extend the existing CUDA FP8 test with a 4D K-cache KQ case:

- K storage is `GGML_TYPE_FP8_E4M3_E8M0_32` with shape
  `[head_dim * n_head_kv, n_kv]`.
- K is reshaped to `[head_dim, n_head_kv, n_kv, 1]` and permuted to the runtime
  KQ layout `[head_dim, n_kv, n_head_kv, 1]`.
- Q storage is F32 with shape `[head_dim, n_head, n_tokens, 1]` and is permuted
  to `[head_dim, n_tokens, n_head, 1]`.
- The test compares `mul_mat(K_fp8, Q_f32)` against `mul_mat(K_f32, Q_f32)`.
